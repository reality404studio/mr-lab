# 정보 부족 및 사용자 결정 필요 명세

`DESIGN.md`에 명시되지 않았거나 실제 현장 구동 전에 결정이 필요한 항목입니다.

## 1. 배포/보안 컨텍스트

WebXR은 HTTPS 또는 브라우저가 인정하는 보안 컨텍스트가 필요합니다. Quest 기기에서 `http://<LAN-IP>:8080` 접속이 WebXR 시작을 막으면 아래 중 하나를 결정해야 합니다.

- HTTPS 배포 호스트 사용
- 로컬 HTTPS 인증서 구성
- HTTPS 터널 사용

## 2. Quest MR 세션 모드

구현은 `immersive-ar`를 먼저 시도하고 실패하면 `immersive-vr`로 폴백합니다. 최종 체험이 반드시 패스스루 MR이어야 한다면 대상 Quest Browser 버전과 배포 환경에서 `immersive-ar` 지원을 실기기로 확인해야 합니다.

## 3. WebXR 시작 제스처

문서의 `BOOT`는 앱 로드 시 WebXR 초기화를 전제하지만, 실제 브라우저는 사용자 제스처 없이 XR 세션을 시작할 수 없습니다. 현재 구현은 앱 로드 후 `XR 시작` 버튼을 눌러 세션을 시작합니다.

## 4. SSE 서버 명세

클라이언트는 `?mode=custom&sse=/events`를 지원하지만 서버 자체는 포함하지 않았습니다. 서버는 아래 형식 중 하나로 텍스처를 보내야 합니다.

```json
{ "id": "student-001", "texture": "data:image/png;base64,..." }
```

```text
data:image/png;base64,...
```

결정 필요:

- SSE 엔드포인트 URL
- 학생 큐 순서 보장 방식
- 연결 재시도/만료 정책
- 여러 Quest 기기가 같은 큐를 볼 때의 분배 정책

## 5. 교사용 촬영/크롭 앱

`DESIGN.md`의 교사 폰 브라우저 촬영, 원 감지, QR 파인더 패턴 감지, 원근 보정, 512x512 PNG 업로드는 이번 구현에 포함되지 않았습니다. 별도 클라이언트와 서버 작업으로 분리해야 합니다.

## 6. 텍스처 품질 규칙

현재 게임 클라이언트는 이미 전처리된 PNG를 받는다고 가정합니다. 아래 처리의 최종 기준값을 확정해야 합니다.

- 원형 마스크의 페이드 시작 반지름
- 업로드 이미지 최대 용량
- 실패 이미지 검증 UI
- 학생 이름/ID와 텍스처 매핑 방식

## 7. Game Over 이후 다음 학생 흐름

문서에는 `다음 학생 선택 + 큐에 텍스처 있음`과 `BEAT_3 이후 큐 확인`이 함께 적혀 있습니다. 현재 구현은 플레이어가 `다음 학생`을 선택했을 때 큐가 있으면 다음 텍스처로 전환하고, 큐가 없으면 custom 모드에서 대기 화면으로 갑니다.

## 8. 입력 정책

현재 구현은 Quest 컨트롤러 Grip으로 구슬을 잡고 Trigger/Grip으로 Game Over 선택을 처리합니다. 손 추적, 양손 제스처, 시선 선택, 컨트롤러 없는 모드는 아직 정책이 없습니다.

## 9. 실기기 튜닝

아래 값은 `src/config.js`에서 조정 가능하지만, 실제 교실 공간과 학생 연령에 맞춰 실기기 테스트가 필요합니다.

- 오브 스폰 거리와 높이
- 그랩 판정 반경
- 먹기 판정 거리
- 꼬리 충돌 거리
- HeadSphere follow distance

## 10. 구현상 추론으로 확정한 정책

아래 항목은 `DESIGN.md`에 엄격한 정책이 없어서, 현재 프로토타입 구현에서 임시로 정한 기준입니다. 실기기 테스트 전 최종 정책으로 확정하거나 수정해야 합니다.

| 항목 | 현재 구현에서의 추론 | 확정 필요 이유 |
|---|---|---|
| 월드 좌표계 | WebXR `local-floor`를 우선 사용하고 실패하면 `local`을 사용합니다. 수평 이동 기준은 플레이어 head/viewer forward를 바닥면으로 투영한 방향입니다. | Quest 공간 기준, 바닥 원점, 재센터링 정책이 명시되어야 스폰/충돌/뒤따라오기 감각이 일관됩니다. |
| 전방/후방 기준 | 플레이어의 현재 시선 방향을 전방으로 보고, HeadSphere는 `playerPos - forward * followDistance` 위치에 둡니다. | 사용자가 몸을 돌리는 것과 고개만 돌리는 것을 같은 기준으로 볼지 결정해야 합니다. |
| 높이 기준 | HeadSphere, 오브, HUD는 viewer/head 높이를 기준으로 배치합니다. 실제 바닥 높이나 학생 키 보정 정책은 없습니다. | 어린이/성인 키 차이, 앉은 자세, Guardian 바닥 보정 상태에 따라 체감 위치가 달라집니다. |
| READY 스폰 기준 | READY 진입 시 현재 플레이어 위치와 시선 방향을 기준으로 HeadSphere와 FoodOrb 3개를 생성합니다. | 시작 버튼을 누른 순간의 방향을 기준으로 할지, 별도 캘리브레이션 포즈를 요구할지 결정해야 합니다. |
| FoodOrb 개수/색 | 필드에는 빨강, 노랑, 파랑 FoodOrb를 각 1개씩, 총 3개 유지합니다. 먹힌 색상은 같은 색상으로 즉시 1개 재스폰합니다. | 개수와 색상은 `DESIGN.md`를 따른 것이지만, 난이도 조절용으로 색상 수/동시 개수를 바꿀지 결정할 수 있습니다. |
| FoodOrb 랜덤 배치 | 플레이어 주변 0.85m-1.35m 반경, head 높이 기준 -0.18m-+0.22m 범위에서 랜덤 배치합니다. 플레이어와 최소 0.8m 거리를 보장하려고 최대 24회 후보를 뽑습니다. 벽/가구/Guardian 경계는 고려하지 않습니다. | 실제 MR 공간에서는 오브가 물리 장애물이나 플레이 영역 밖에 생길 수 있습니다. |
| 컨트롤러 입력 | Grip 버튼은 그랩/다음 학생, Trigger는 Game Over 후 다시하기로 매핑했습니다. | Quest 컨트롤러 모델, 손 추적 사용 여부, 어린이 조작 난이도에 맞춰 입력 정책을 확정해야 합니다. |
| SSE 큐 반영 | 플레이 중 또는 현재 텍스처가 있는 상태에서 수신한 텍스처는 큐에 저장합니다. 다음 학생 선택 시 하나씩 꺼냅니다. | 문서에는 `BEAT_3 이후 큐 확인`과 `다음 학생 선택`이 함께 있어 자동 전환 여부가 모호합니다. |
| preset 모드 SSE | `?sse=`가 있으면 preset 모드에서도 큐 수신을 허용합니다. | preset을 완전 독립 모드로 둘지, 현장 테스트용 기본 텍스처 + 큐 수신 모드로 둘지 결정해야 합니다. |
| 충돌 판정 시점 | BodySegment가 1개 이상 생긴 뒤 꼬리 끝 하나만 플레이어 head/viewer 위치와 거리 비교합니다. | 충돌 기준을 실제 머리 위치, HeadSphere 위치, 또는 몸통 전체 중 무엇으로 볼지 정책이 필요합니다. |
| 개발 미리보기 | Desktop 검증용 `?preview=1`은 WebXR 세션이 아니라 가상 카메라/키보드 입력으로만 동작합니다. | Quest 실기기 결과와 1:1 검증 수단이 아니므로, QA 기준에서 분리해야 합니다. |
